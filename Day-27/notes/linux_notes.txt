Linux Notes - Day 27

1. Why unquoted | breaks a grep -E pattern (today's big lesson)
   grep -iE ERROR|WARNING|FAILED LOGIN        <- WRONG
   The shell reads this BEFORE grep ever sees it. Every unquoted | is
   treated as a literal pipe between two commands. So the shell tries
   to run "WARNING" as its own program -> "command not found".

   grep -Ei "ERROR|WARNING|FAILED LOGIN" logs/*.log | wc -l   <- RIGHT
   Quotes force the shell to treat the whole pattern as ONE argument.
   Only then does grep's -E (extended regex) get to interpret the |
   as "OR" inside the pattern itself.

   Rule of thumb: any time a regex pattern has a special shell character
   in it ( | * ? $ ( ) ), wrap the pattern in quotes.

4. Data hygiene reminder
   A leading space in a value (" cloud engineer" instead of
   "cloud engineer") or a truncated word ("Networ") looks like a small
   thing but breaks exact-match searches later (grep "cloud engineer"
   would miss the line with the leading space). Proofread data files
   before running extraction commands on them.
